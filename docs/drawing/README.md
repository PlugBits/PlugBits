# 類似図面検索 LP — Brevoフォーム設定

このLP(`/drawing/`)のフォームは、Brevo(旧Sendinblue)のフォームに `no-cors` でPOSTするだけの、依存ゼロの実装です。設定手順は次のとおりです。

## 1. Brevoでリストとフォームを作る

1. Brevo管理画面で、新規リスト `drawing-waitlist` を作成する。
2. そのリストに紐づく新規フォームを作成する。
3. フォームのフィールドを、このLPが送信する項目に合わせる。
   - `EMAIL` … メールアドレス(必須)
   - `LASTNAME` … 会社名(任意)。Brevo側フォームがLASTNAME属性で作られているため、LPもこの名前で送信する
   - フィールド名(内部名)がこの2つと一致しない場合、登録されないので必ず確認する。
4. フォーム作成後、埋め込みコードから action URL(`https://xxxx.sibforms.com/serve/…` の形式)を控える。

## 2. app.js に action URL を設定する

`docs/drawing/app.js` の先頭にある定数を書き換える。

```js
const BREVO_FORM_ACTION = 'https://xxxx.sibforms.com/serve/...';
```

未設定(空文字列)のままだと、フォーム送信時は常に「送信できませんでした。少し時間をおいてもう一度お試しください」が表示されます。

## 3. no-cors送信について

Brevoのsibforms(フォーム埋め込み)エンドポイントはCORSヘッダを返さないため、`fetch` は `mode: 'no-cors'` で呼び出しています。この場合レスポンスは常に opaque(中身を読めない)になるため、**送信の成否をレスポンス内容から判定できません**。

このLPでは次の方針にしています。

- `fetch(...).then(...)` が呼ばれた(=ネットワークエラーが起きなかった)時点で成功とみなす。
- ネットワークエラー(オフライン、DNS失敗など)で `fetch` が reject したときだけ、失敗メッセージを表示する。

つまり、Brevo側でフォームの必須項目が未入力/フィールド名の不一致などでサーバー側から実質的に弾かれていても、LP側は成功表示になり得ます。フィールド名の設定(上記1〜2)は特に注意してください。

## 4. 計測

フォーム送信が成功したとみなされたタイミングで、`history.pushState({}, '', '/drawing/thanks/')` を呼んでいます。これにより、Cloudflare Web Analytics(SPAのページ遷移をページビューとして記録する)側で `/drawing/thanks/` への仮想ページビューが記録され、これがフォーム送信イベントの計測代わりになります。`/drawing/thanks/` に実体のページは存在しません。
